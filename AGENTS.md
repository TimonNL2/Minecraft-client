# Release preferences

- After completing and validating requested client changes, commit and push them to GitHub and publish a new numbered release using the existing release workflow.
- Use a new version and tag for each release. Preserve all existing releases, tags and download assets; do not overwrite or delete them.
- Keep Minecraft-version-specific feature requests restricted to the version the user requested.
- Build, test and publish new releases only for Minecraft 26.3. Keep 26.2 downloads in their previous releases; do not publish new 26.2 jars unless explicitly requested.
- Verify the release workflow and downloadable assets before reporting publication as complete.
